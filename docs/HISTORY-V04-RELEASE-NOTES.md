# ADVERSE JUDGE v0.4.0 — эксплуатационное укрепление

**Дата:** 22 октября 2026. **Статус:** локальный пилот / закрытый staging-кандидат, **не production и не публикация на семи сайтах**.

## Реализовано

1. SQLite миграция 2→3: device label (без полного User-Agent), lastSeenAt для сеансов, `auth_failures`, `redeem_request_hash`.
2. Серверные API `GET /api/auth/sessions`, `POST /api/auth/sessions/revoke`, `POST /api/auth/password` и UI активных сеансов + смены пароля.
3. Защита от подбора логина с постоянным счётчиком неудачных попыток по хэшу email и дополнительным IP ограничением.
4. Возобновляемая по одинаковому `requestId` и в течение пяти минут подписанная передача; no-replay с другими ключами; подтверждённые actions сохраняют прежнюю идемпотентность.
5. SDK для серверов партнёров с pinned HTTPS judgeOrigin, редирект запрещён, ограничен таймаут и размер ответа.
6. `/api/ready`, `npm run ops:doctor`, `npm run backup:inspect -- path`, репетиция SQLite восстановления и SHA-256.
7. Конфигурация **закрытого staging** через Caddy/Docker (не проверена в этом окружении), runbook для оператора, RFC Postgres/Supabase.
8. Реальное приложение и автономный preview пересобраны; экран настроек адаптирован под мобильный размер.

## QA

- 105 автоматических Node проверки (включая новые HTTP, миграционные, SDK, security и backup-сценарии).
- 22 browser UI проверки с настоящим локальным API через тестовый HTTP bridge, включая смену пароля и активные сеансы.
- Независимый HTML-only smoke: claim→three paths→verdict→clipboard export.
- Отдельный smoke старого v0.3 ZIP → новой v0.4 версии БД: описан в QA report.

## Границы

**Не подключены:** реальные семь API/сайтов, Supabase/PG, OpenAI оплаченный вызов, верификация email/SSO/MFA, платежи и внешняя инфраструктура. Docker/Caddy — файлы для оператора, не подтверждённая публикация. Цифры/скриншоты из QA относятся к синтетическим событиям локального стенда.

Перед миграцией обязательно сделать резервную копию; обратная совместимость SQLite v3 с бинарником v0.3 не обещается.
