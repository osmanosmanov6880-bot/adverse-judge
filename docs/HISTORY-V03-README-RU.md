# JUDGE / ADVERSE · 0.3.0

**Рабочий локальный пилот «Суда над обещанием», релиз с версионированными передачами, управлением отзывом и проверкой интеграционного контракта.** Не чат, не сгенерированный макет и не готовая международная SaaS-платформа.

## Открыть

Требуется Node.js **22.13+**; проверка выполнена на 22.16.0. Поддержка других версий без их запуска здесь не заявляется. Для рабочей эксплуатации используйте поддерживаемую исправленную версию Node и повторите тесты.

В распакованной папке:

```bash
npm start
```

Откройте в браузере:

```text
http://localhost:3000
```

На Windows можно дважды нажать **START_WINDOWS.cmd**. На macOS/Linux: `sh start.sh`.
Установка npm-зависимостей не нужна: сервер использует встроенные модули Node.js. Предупреждение `ExperimentalWarning: SQLite` в Node 22 ожидаемо; это не сообщение о потере данных.

Если порт занят, завершите только ранее запущенный JUDGE либо задайте другой PORT и согласованный APP_ORIGIN в локальном `.env`. Не завершайте все процессы компьютера.

## Посмотреть без установки

`dist/JUDGE-ADVERSE-preview.html` — отдельный интерактивный HTML-файл. Откройте его в браузере: доступны три ветки, редактор, бриф и экспорт. Он **не заменяет сервер**: нет аккаунтов, обмена возражениями между людьми, внешних интеграций или живого ИИ. Сохранение использует localStorage браузера; при запрете хранилища данные живут только до закрытия страницы.

## Что нового в 0.3.0

- **Подтверждение версии**: signed handoff привязан к `verdictId`. Передача из старой редакции не погашается после пересмотра, возражения или нового вердикта.
- **Явный отзыв** подписанной ссылки до первого получения внешней платформой. В каждом деле появилась история передачи с честными статусами «подготовлен», «получен», «отозван», «подтверждено действие».
- **Усиленный callback**: повтор одного внешнего `eventId` с теми же данными не увеличивает счётчики; повтор с другим `handoffId`/`action` возвращает конфликт.
- **Контроль конфигурации A–G**: проверяются адреса HTTPS, манифест, отдельные серверные секреты, allowlist событий. Команды `npm run integrations:check` и `npm run integrations:strict`. Контракт для принимающего сайта — `docs/INTEGRATION-CONTRACT-RU.md`.
- **Миграция SQLite `user_version=1 → 2`** без переписывания дел; прежние handoff без `verdict_id` не могут быть погашены. Обязательно сделайте копию старой базы перед первым запуском нового сервера.
- **Защитный запрет на публичное HTTP** без HTTPS-origin. Подключать сайт к интернету всё равно нельзя без внешней инфраструктуры и производственной авторизации.
- Проверки: 91 автоматический тест и 20 браузерных сценариев, в том числе приём подписанной передачи тестовым партнёром и отзыв ссылки. Реальных сайтов это не проверяет.

## Ранее реализовано в 0.2.0

- Повторный пересмотр автором после завершённого вердикта: предыдущая версия хранится в журнале, новые изменения приводят к новому `verdictId`; ссылки свидетелей на старый вердикт отзываются.
- Персональная аналитика на `/analytics`: семь стадий воронки по **уникальным делам** и последние 14 дней выпусков брифов. События выдачи брифа, подготовки handoff, получения handoff и подтверждения действия **не смешиваются**.
- В каждом деле — сверка сохранённого состояния с восстановленным по событиям и редакторское сравнение формулировки. При расхождении журнал/снимок изменяющие операции блокируются.
- Экспорт структурированного JSON-брифа с предупреждениями и статусом основания. Есть серверный маршрут `GET /api/cases/:id/brief` только для владельца и завершённого брифа.
- Резервная копия SQLite через официальный backup API, с проверкой структурной целостности, реконструкции событий и SHA-256. Команды `npm run backup`, `npm run verify`.
- Отдельные проверки новых маршрутов, доступа, пересмотра, восстановленного состояния и живой SQLite-копии.

Это улучшенный **локальный пилот**, а не публичная production-SaaS: нет подтверждённой SSO семи сайтов, облачной базы, почтовой верификации, восстановления пароля и реальной интеграции с рекламными сайтами.

## Что уже работает

- Русский адаптивный кабинет: обзор, новое дело, рассмотрение, варианты, вердикт, история, платформы и настройки.
- Три действия: уточнить обещание, предъявить основание, изменить подход.
- Серверная проверка переходов: нельзя перескочить прямо к вердикту, пропустить согласие или заменить чужое дело.
- Подготовка трёх шаблонных вариантов строго из данных автора. Итоговый текст можно изменить вручную.
- Сохранение в SQLite и событийный журнал; проверена реконструкция состояния из журнала.
- Гостевая сессия, локальный аккаунт с паролем, вход/выход и перенос гостевых дел при входе.
- Экспорт брифа в TXT и структурированный JSON, копирование, выгрузка своих данных в JSON, удаление из активной базы.
- Одноразовая отзываемая ссылка свидетеля на семь дней; настоящее возражение другого пользователя открывает дело повторно.
- Каркас семи адаптеров A–G: копирование доступно; настроенный подписанный deeplink поддерживает серверное получение брифа и подтверждение события.
- Опциональный серверный адаптер OpenAI Responses API. Без конфигурации работает явно подписанный сценарный режим.

## Первый тест за один проход

1. Нажмите «Открыть первое дело».
2. Выберите «Уточнить обещание».
3. Проверьте факты учебного примера и нажмите «Собрать формулировки».
4. Выберите подход, отредактируйте текст, подтвердите понимание ограничений и зафиксируйте бриф.
5. Скачайте TXT. Перезагрузите страницу: дело должно сохраниться.
6. Нажмите «Вызвать свидетеля», подтвердите раскрытие итоговой фразы и аудитории.
7. Откройте ссылку в **приватном окне или другом браузере**. Отправьте возражение.
8. В исходном окне обновите дело: появятся возражение и возможность ответить или пересобрать текст.

Ссылка `localhost` работает только на компьютере, где запущен сервер. Для настоящего приглашения удалённого человека потребуется развёртывание за HTTPS. Эта сборка не опубликована на вашем сервере.

## Данные и доступ

По умолчанию файл базы: `data/judge.sqlite`. Не удаляйте папку `data`, если нужно сохранить работу. Не переносите только основной sqlite-файл, пока сервер пишет данные: корректно остановите сервер или используйте согласованный механизм резервного копирования.

Гостевая сессия действует семь дней. Без аккаунта после потери cookie доступ к гостевым делам восстановить нельзя. Дела гостя автоматически не удаляются по истечении cookie: отдельная политика очистки пока не внедрена.

Аккаунт — **только этого JUDGE**, не общая учётная запись ADVERSE. Email не проверяется; восстановления пароля и MFA нет. Не используйте пароль от других сервисов. Нельзя использовать эту авторизацию как подтверждение личности или владельца почты.

Ссылка свидетеля раскрывает только финальную фразу и аудиторию. Любой обладатель действующей ссылки может их прочитать. Не помещайте туда секреты. Самоссылка отклоняется по идентификатору сессии/аккаунта, а не по реальному человеку: второй браузер не доказывает независимость свидетеля.

## Живой ИИ

По умолчанию **отключён**, деньги API не расходуются. Сценарные роли и шаблонные варианты не маскируются под ответы модели.

В коде есть серверный адаптер Responses API с JSON Schema, тайм-аутом, ограничением ответа, лимитом запросов и явным согласием в интерфейсе. Для подключения используйте защищённый процесс создания ключа OpenAI Platform; не отправляйте ключ в чат и не помещайте в HTML/клиентский JS. Поля конфигурации перечислены в `.env.example`.

Модель задаётся оператором, исходя из доступа его API-проекта. Ключ, фактический доступ, биллинг и живой ответ провайдера в этой сборке **не проверены**. Адаптер протестирован на контрактных фикстурах. `store:false` не является гарантией нулевого хранения данных у провайдера.

ИИ комментирует формулировку, но не получает инструментов, не изменяет факт, фазу, решение, внешнюю интеграцию или статистику успеха. Комментарий сохраняется отдельным событием и может устареть после редактирования дела.

## Семь работающих платформ

Их URL, API и способы авторизации не предоставлены. Поэтому `config/platforms.json` содержит ровно семь **ненастроенных** подключений. Названия A–G — технические места для конфигурации, не присвоенные им продуктовые функции.

Копирование брифа ≠ доставка на сайт ≠ регистрация ≠ созданная реклама. `useful_action` появляется только после аутентифицированного callback согласованного типа. Это подтверждение внешней системы, а не независимый аудит эффективности.

Прямой API-адаптер без контракта возвращает `NOT_CONFIGURED`. Не заменяйте это поведение выдуманным успешным ответом. Подписанный deeplink и пример настройки описаны в `docs/INTEGRATION-CONTRACT-RU.md` и `docs/API.md`; тест использует только фиктивный example.com и никогда не отправляет туда реальный заказ.

## Проверить сборку

```bash
npm run check
npm test
npm run demo
npm run verify    # при существующей data/judge.sqlite
npm run backup    # при существующей data/judge.sqlite
```

Браузерный тест: `python scripts/browser-smoke.py` — требует Python Playwright и Chromium, которых самому приложению не нужно. В среде сборки навигация Chromium на URL заблокирована политикой: HTML/CSS/JS встроены в тестовую страницу, а запросы идут в реальный локальный сервер через контролируемый HTTP-мост. Поэтому cookie-флаги, Host, Origin и CSRF проверяются отдельно в Node HTTP-тестах, а не объявляются проверенными нативной браузерной навигацией.

Результаты: `reports/TEST-REPORT.md`, `reports/unit-tests-v0.3.tap`, `reports/browser-results.json`. Скриншоты сделаны из интерфейса, построенного из поставляемого кода.

## Что НЕ завершено

PostgreSQL/Supabase, RLS на реальном облачном проекте, SSO семи сайтов, производственные платежи, MFA, почта, восстановление пароля, проверка рекламных фактов, юридическая экспертиза, реальная статистика конверсий, публикация на вашем домене, внешние API сайтов и нагрузочная проверка не заявляются выполненными.

Вместо прежнего предлагаемого Next.js/TypeScript/Supabase здесь выбран запускаемый без облачных секретов вертикальный прототип: browser ES modules + Node HTTP + SQLite. Это намеренное ограничение первой сборки. Переход к производственной архитектуре описан в `docs/TECHNICAL-SPEC.md`.

## Структура

```text
public/        интерфейс, стили, API-клиент и preview-адаптер
shared/        чистая модель состояний и правила
server/        HTTP, SQLite, сервис, безопасность, адаптер ИИ
config/        конфигурация платформ A–G
scripts/       сборка превью, синтаксис, интеграционный doctor, браузерная проверка, backup и read-only verify
tests/         доменные, сервисные, HTTP и контрактные тесты
reports/       фактические результаты испытаний
docs/          техническая спецификация, API, ограничения и план развития
dist/          автономное интерактивное превью
```

Локальный пилот следует тестировать на учебных и не конфиденциальных данных. Наличие защитных механизмов и тестов не заменяет независимый аудит безопасности перед публичным запуском.
