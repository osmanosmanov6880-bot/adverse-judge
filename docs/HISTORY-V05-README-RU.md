# ADVERSE JUDGE 0.5.0 — Суд над обещанием + Evidence Room

**Статус: рабочий локальный пилот, не опубликован на семи рекламных платформах, не production.**

JUDGE превращает рекламное утверждение в редакторский вердикт: исходный текст → обвинение → три линии защиты → ввод проверяемых фактов автором → три варианта → финальный бриф. Весь процесс записывается как события SQLite; ИИ, если владелец включит API и даст согласие, может только комментировать.

**Новый этап 0.5.0: Evidence Room.** Можно проверить исходную и итоговую рекламные формулировки на приглашённых живых читателях: две фразы без пометки версии, сбалансированный порядок, индивидуальная одноразовая ссылка, голос «первый/второй/ни один», необязательная причина и агрегаты для автора. Только реальные ответы. **Это не рекламный A/B-тест и не прогноз продаж.**

## Как запустить

Требуется Node.js 22.13+ (проверено на 22.16.0). В распакованной папке проекта:

```bash
npm start
```

Откройте `http://localhost:3000`. На Windows — `START_WINDOWS.cmd`. Для автономного просмотра без Node откройте `dist/JUDGE-ADVERSE-preview.html`: там работает разбор и экспорт, но **нет настоящего совместного опроса**.

**Быстрый маршрут:** «Открыть первое дело» → «Уточнить обещание» → «Собрать формулировки» → «Зафиксировать бриф» → **«Создать слепой тест»** → «Пригласить читателя». Второй человек открывает персональную ссылку в другом браузере и голосует. Владелец возвращается в дело и нажимает «Обновить». Для теста на другой машине вместо `localhost` нужен доступный HTTPS-сервер.

## Что сохранено из 0.4

- Три линии редакторского разбора, роли Лекс/Аврора/Свидетель, сохранение историй и вердиктов, JSON/TXT бриф.
- Гостевые дела, локальные аккаунты и доступ к ним, управление сеансами и смена пароля.
- Настоящий свидетель с одноразовой ссылкой и возражением, повторный выпуск вердикта.
- Защищённый контракт handoff/deeplink для **потенциальных** интеграций, отзыв неподтверждённых передач и аутентифицированные подтверждения действий.
- Диагностика `npm run ops:doctor`, проверка event replay, резервирование/проверка SQLite и автономное HTML-превью.

## Новое в 0.5

- `server/comparison.mjs`: неизменяемый снимок исходной и итоговой формулировок, агрегаты голосов без «AI-выдумки».
- `comparisons`, `comparison_links`, `comparison_votes`: SQLite v4 с транзакциями, ограничениями, TTL и каскадным удалением.
- `#/compare/<token>` — публичная карточка приглашённого участника, не требующая регистрации.
- Изменение исходного вердикта автоматически прекращает старый опрос. Итоги старых голосов остаются только у владельца.
- Расширены приватный экспорт, API и тесты. Пароли, гостевые cookie, хэши ссылок и секреты не попадают в отчёты.

## Проверки


## Обновление с 0.4.0

Остановите 0.4.0, сделайте проверенную копию `data/judge.sqlite`, распакуйте новую версию отдельно и только затем перенесите файл базы или укажите путь через `JUDGE_DB`. `Store` при первом запуске мигрирует `PRAGMA user_version=3` в `4`, не удаляя дела, версии, сессии и handoffs. `npm run verify` должен успешно восстановить события. Для отката используйте **сохранённую старую базу**: старый код 0.4 не может открыть новую схему 4. Подробнее — `docs/OPERATIONS-RU.md`.

## Что пока не готово

Реальные подключения A–G остаются ненастроенными: от пользователя не было адресов/подтверждённых контрактов; показанные ручные экспорты **не считаются доставкой**. Общая авторизация семи сайтов, подтверждение email, MFA, парольное восстановление, облачный Postgres, многосерверный runtime и настоящий платежный приём отсутствуют. Текущие опросы не защищены от накрутки разными гостевыми сеансами и не рассчитаны на открытый интернет без дополнительной защиты.
