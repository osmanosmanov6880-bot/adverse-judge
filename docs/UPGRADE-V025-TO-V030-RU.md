# Обновление JUDGE 0.25.0 → 0.30.0

**Внимание:** это руководство для автономного локального пилота, не разрешение на публичный запуск.

1. Остановите предыдущий сервер и операторский воркер (если запускали). Не обновляйте приложение во время активной передачи пакета.
2. Создайте **настоящую резервную копию** командой `npm run backup -- /safe/location/JUDGE-pre030.sqlite` из исходной установки. Не копируйте SQLite-WAL файлы вручную. Проверьте её: `npm run backup:inspect -- /safe/location/JUDGE-pre030.sqlite`.
3. Сохраните отдельно секреты `HANDOFF_SECRET`, `JUDGE_LEDGER_SECRET` (если установлен) и конфигурацию `JUDGE_PLATFORMS_FILE`. Их потеря может нарушить проверку истории и подписанных ссылок. Не вставляйте секреты в чат/скриншоты.
4. Распакуйте релиз 0.30.0 в **новую папку**. Не заменяйте и не удаляйте прежнюю базу.
5. Укажите путь к старой базе в переменной `JUDGE_DB` и оставьте прежние секреты. В изолированной проверочной копии выполните `npm test` и `npm run verify`, затем проверьте новые таблицы.
6. Запустите `npm start`, откройте `http://localhost:3000`, пройдите дело, приглашение второго редактора, существующую кампанию и выпуск. Откройте «WAVE 21–25» из кампании.
7. Для реального почтового подтверждения отдельно настройте **защищённый HTTPS mail webhook**, затем проверьте доставку и возврат кодов. Только после миграции существующих аккаунтов безопасно включать `JUDGE_REQUIRE_VERIFIED_EMAIL=1`.
8. Для внешней отправки заполните и независимо проверьте контракт конкретного партнёра, настройте отдельные серверные секреты HMAC и callback, подпишите тестовый запрос и подтвердите идемпотентность. Если контракта нет — оставьте партнёра неподключённым.
9. Выполните `npm run production:doctor` и расследуйте реальные блокеры. В этом релизе `productionReady:false` ожидаем.

**Проверено при выпуске:** миграция из тестовой базы, созданной подлинным кодом JUDGE 0.25.0: SQLite 22→27, сохранение дела, двух участников команды, редакторского утверждения и SHA-256 пакета.

**Откат:** не понижайте схему 27 до схемы 22. Для отката восстанавливайте проверенную резервную копию старой версии и старый код. Редакции, созданные в 0.30.0 после обновления, не перенесутся обратно.
