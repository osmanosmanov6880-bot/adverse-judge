# Evidence Room 0.5 — спецификация и модель доверия

## Зачем

JUDGE уже превращает обещание в редакторский бриф, но не даёт доказательства, что текст действительно понятнее живому читателю. Evidence Room проверяет узкую гипотезу: **какой текст людям проще понять с первого прочтения**. Сначала редакторский вердикт, потом добровольный человеческий опрос. Ни ИИ, ни имитация аудитории не создают голосов.

## Пользовательский маршрут

1. Открыть старое или создать новое дело. Пройти три редакторских шага и зафиксировать вердикт.
2. В блоке «Проверка понятности на людях» создать тест с согласием показать два текста обладателям ссылок.
3. Создать индивидуальную одноразовую ссылку и послать конкретному человеку. Никакой обязательной регистрации.
4. Приглашённый видит **только две фразы**, в последовательности 1/2, без намёка, какая «новая», и отвечает `первый/второй/ни один`. Необязательный комментарий видит автор.
5. Автор наблюдает реальные ответы, а не прогнозы и не «скоринг эффективности». Может закрыть сбор вручную.
6. При изменении вердикта старые опросы становятся историческими и не принимают новые ответы.

## Ограничения метода

Это **convenience-sample comparison**, не контролируемый рекламный A/B-тест. Участников выбирает автор, лимит 30 персональных ссылок; нет проверки независимости, реального охвата, случайной репрезентативной выборки, бот-фильтрации, идентичности и рекламных KPI. Балансировка порядка снижает простую позиционную предвзятость, но не устраняет выборочную. Нельзя делать выводы о CTR, продажах, эффективности, причинности или достоверности заявленных фактов.

## Модель данных (SQLite schema_version 4)

- `comparisons`: `id`, `case_id`, `verdict_id`, `question`, `variant_a`, `variant_b`, `seed`, `status`, `created_at`, `expires_at`, `closed_at`. Значения вариантов **снимки на момент выпуска**, они не переписываются при следующем вердикте.
- `comparison_links`: `id`, `comparison_id`, `token_hash`, `display_order`, `created_at`, `expires_at`, `used_at`, `revoked_at`. Нет открытых токенов в БД, реестре событий и экспорте.
- `comparison_votes`: `id`, `comparison_id`, `link_id UNIQUE`, `selection`, `note`, `created_at`. Один ответ на одну ссылку, ограничения в SQL и транзакция.

Связанные значения удаляются каскадно вместе с делом. Журнал `events` отмечает создание теста, выдачу ссылки, действительный голос, закрытие и инвалидацию. `audit` точно воспроизводит состояние **основного дела**; подсчёт голосов проверяется отдельно SQL-агрегацией, а не вычисляется LLM.

## Сценарии угроз и меры

| Угроза | Мера в MVP | Остающийся риск |
|---|---|---|
| Угадывание ссылки | 256-битный случайный токен, SHA-256 в БД, срок до 7 дней | Пересылка уже полученной ссылки третьим лицам |
| Повторный голос | `link_id UNIQUE` и `used_at` внутри одной транзакции | Множество разных ссылок одному человеку |
| Позиционный эффект | 50/50 сбалансированный `display_order` для последовательных приглашений | Малые выборки, рекрутинг автором |
| Доступ к результатам чужого дела | Проверка `owner_id` + CSRF/Origin | Компрометация локального аккаунта |
| Устаревшие тексты | `verdict_id` + `phase` + `invalidated` при reopen | Ранее скопированные тексты нельзя удалить из памяти читателей |
| XSS из комментария | HTML-экранирование, CSP, лимит 500 символов | Публичный прод требует независимого пен-теста |
| Автоматическое голосование | Лимит запросов по IP + одноразовые токены | Отсутствуют CAPTCHA, верификация email и анти-Sybil |
| Утечка персональных данных | Минимальный публичный payload, согласие, удаление/export | Оператор должен определить сроки хранения, уведомления и DSAR |

## Интеграция с остальными системами

Evidence Room не отправляет рекламные материалы на A–G и не подменяет собой аналитику. После получения откликов автор может **сам** перейти к генерации материала через существующий clipboard fallback JUDGE. Адаптеры семи платформ по-прежнему имеют статус unverified/not_configured.

## Условия принятия

- Все 3 направления защиты, вердикт, witness и handoff прошлых версий продолжают работать.
- Гость проходит опрос без создания локального аккаунта.
- Автор не может голосовать со своей собственной cookie.
- Голос записывается один раз и не раскрывается второму участнику.
- Начальное/новое сообщение показываются в обратном порядке на следующих двух ссылках.
- По реальному возражению свидетеля авторская карточка становится invalidated, но старые результаты доступны.
- Миграция `SQLite PRAGMA user_version 3 → 4` не стирает дела, события и сессии.
- Прежний 0.4 сервер нельзя запускать с мигрированной v4 базой. Нужна заранее сделанная резервная копия для отката.
