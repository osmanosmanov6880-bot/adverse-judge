# JUDGE v0.4 — интеграция работающих рекламных сайтов

**Статус:** протокол и SDK реализованы; реальные A–G ещё не подключены. Никакие адреса/API не подставлены по догадке. Тестовый приём не доказывает готовность пользовательской платформы.

## Что нужно от администратора каждого сайта

- Подтверждённый домен и HTTPS endpoint приёма токена (`/judge-import` — пример, не реальный путь).
- Согласие на серверную авторизацию и хранение брифа; правила удаления и срок хранения.
- Подтверждённый перечень реальных событий (например `ad_created` лишь если объявление действительно создано, а не нажата кнопка).
- Надёжное хранение `requestId` и `eventId` в собственной БД сайта, до сетевого запроса.
- Отдельный секрет JUDGE ↔ конкретная платформа, ротация и мониторинг.

## Подключение receiving SDK

Модуль `integrations/receiver-sdk.mjs` рассчитан на Node.js >=22.13 **на сервере принимающего сайта**. Он никогда не должен попадать в браузерный бандл. В нём нет зависимостей npm.

```js
import {createJudgeReceiver} from './integrations/receiver-sdk.mjs';

const judge=createJudgeReceiver({
  judgeOrigin: process.env.JUDGE_ORIGIN, // HTTPS адрес JUDGE
  platformId: 'A',
  credential: process.env.JUDGE_RECEIVER_CREDENTIAL
});

// ВАЖНО: receiverRequestId должен быть ранее создан и сохранён в БД принимающего сайта.
// Если JUDGE выполнил redeem, но ответ потерялся, повторите ТОТ ЖЕ requestId в течение 5 минут.
const incoming=await judge.redeem({token:judgeToken,requestId:receiverRequestId});

// Сохраните incoming.handoffId и incoming.brief в собственном защищённом хранилище.
// Только ПОСЛЕ реального выполнения действия на сайте и с тем же неизменным eventId:
await judge.confirm({handoffId:incoming.handoffId,eventId:persistedExternalEventId,action:'ad_created'});
```

Переводити token/credential в query string, frontend или analytics **нельзя**. Исходный `judge_token` принимается только вашим backend. Не логируйте его или сырой URL. Одноразовый протокол делает повторный приём возможным только при совпадении `requestId`, учётных данных партнёра и короткого окна; `duplicate:true` не создаёт второго события.

`GET /judge-import?judge_token=...` — внутренний экран принимающего сайта, который должен сразу убрать токен из адресной строки и передать его только своему серверу. Решение для React/Next.js/другого стека зависит от реальной инфраструктуры платформы.

## Принципы метрик

`handoff_created` — пользователь подготовил передачу; `handoff_redeemed` — партнёр запросил бриф; `useful_action` — партнёр подтвердил созданный объект. Только последнее допускается в воронку полезных действий. Симуляторы, localhost и контрактные тесты не являются доказательствами реальных рекламных действий.

## Путь до реального подключения

1. Зафиксировать домен/владельца и API платформы.
2. Создать staging-приёмник и storage для idempotency keys.
3. Согласовать поля брифа, событие `ad_created` и способы удаления.
4. Пройти 401, 403, 409, 410, 429, 5xx, истечение срока, повтор и аварийный restart.
5. Убедиться, что внешний объект действительно существует; только после этого включать подтверждение `useful_action`.
6. Повторить для остальных сайтов A–G с отдельными секретами.
