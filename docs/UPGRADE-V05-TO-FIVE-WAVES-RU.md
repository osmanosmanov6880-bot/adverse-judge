# Операционный регламент обновления v0.5.0 → v0.10.0

**НЕ обновлять без резервной копии.** Обновление меняет `PRAGMA user_version: 4 → 7` и создаёт новые таблицы. v0.5.0 после этого открыть базу не сможет.

## Порядок

1. Завершите старый процесс JUDGE; убедитесь, что другие процессы не пишут в БД.
2. Создайте корректный SQLite backup (встроенной командой `npm run backup` старого JUDGE, либо с помощью SQLite Backup API). Не копируйте один `.sqlite` при активной записи в WAL без надлежащего checkpoint/backup.
3. Проверьте созданную копию старым `npm run backup:inspect` и перенесите её за пределы сервера в отдельное зашифрованное хранилище.
4. Распакуйте v0.10.0 отдельно. Не переносите заполненную `.env` в исходники для публикации. Укажите `JUDGE_DB` на копию/проверенное расположение.
5. Задайте долгоживущий `JUDGE_LEDGER_SECRET` длиной не меньше 32 символов **до первого старта** нового кода либо явно примите unkeyed SHA256 для исключительно локального пилота.
6. `npm start`; миграция создаёт workspace, research и ledger-таблицы; если конфигурация HMAC не соответствует метаданным, запуск прерывается.
7. Остановите сервер. Запустите `npm run verify` с тем же `JUDGE_DB` и `JUDGE_LEDGER_SECRET`.
8. В браузере проверьте не менее одного старого дела с вердиктом, показ истории, старую сессию, Evidence Room, старый экспорт, затем создайте новую команду и исследование.
9. Для отката: остановите v0.10.0, **верните исходную копию БД версии v4** и прежний код v0.5.0. Не делайте `PRAGMA user_version=4` руками: схема от этого не возвращается назад.

## Фактически выполненная репетиция

Из оригинального ZIP v0.5.0 распакован и запущен код `Store/JudgeService/ComparisonService`. Им созданы старый зарегистрированный пользователь, сеанс, разбор дела, финальный вердикт, слепое сравнение, одно голосование — восемь событий и версия состояния 8. Старая база имела `user_version=4`. После открытия её новой `Store` c режимом HMAC получена схема 7. Контроль: `originalState===migratedState`, все 8 исходных событий, голос и сеанс сохраняются, `JudgeService.audit.consistent=true`, `scripts/verify-db.mjs` сообщает `ok=true` и `foreignKeyViolations=0`. Машиночитаемый результат — `reports/legacy-v05-migration-drill.json`.

**Криптографическое предупреждение:** миграция генерирует начальные digest для исторических событий. Это НЕ доказывает, что события не были изменены до миграции.
