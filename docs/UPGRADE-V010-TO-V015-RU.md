# Обновление ADVERSE JUDGE 0.10.0 → 0.15.0

## Перед началом

**Работающую базу нельзя просто заменять новой пустой базой.** Остановите сервер 0.10.0; сохраните исходный архив и проверенный backup всей базы, включая корректный SQLite WAL snapshot. Никогда не копируйте только основной `.sqlite` файл на работающем сервисе с активным WAL, если не делаете SQLite backup API.

1. Остановить JUDGE 0.10.0 и проверить, что ни один процесс не пишет в базу.
2. Сделать резервную копию через штатный скрипт из старой версии; проверить копию (`backup:inspect`) и `PRAGMA integrity_check`.
3. Сохранить прежние переменные окружения, прежде всего `JUDGE_LEDGER_SECRET`. **Без прежнего ключа HMAC база намеренно не откроется.** Не менять ключ при обновлении.
4. Распаковать JUDGE 0.15.0 в **новую папку**. Перенести корректно остановленную или созданную SQLite backup API базу `data/judge.sqlite` либо задать `JUDGE_DB` с нужным абсолютным путём.
5. Запустить Node.js 22.13+ через `npm start` — схема 7 автоматически обновится до 12 внутри транзакции. Выбор API и URL внешних платформ не меняется.
6. Проверить `/api/ready`, `npm run verify`, старые вердикты, участники команд, исследования и голоса. Выполнить `npm test` на чисто распакованной копии.
7. Войти как владелец команды, открыть «Кампании», создать пробную кампанию с подключённым делом.

## Что протестировано

С помощью исходного **кода 0.10.0** создана настоящая тестовая база схемы **v7** с завершённым делом, **8 событиями**, одним голосом слепого теста, одним исследованием, рабочей командой с двумя участниками, комментарием и сохранённой сессией. Тест `tests/migration-v010-to-v015.test.mjs` копирует эту базу и открывает новым Store:

- `PRAGMA user_version` меняется **7 → 12**;
- 8 событий, 1 голос, 1 исследование, 2 члена команды и 1 сессия остаются;
- replay + HMAC журнал старого дела проходят без изменения ключа;
- новая кампания создаётся в мигрированном рабочем пространстве;
- с неверным HMAC-ключом обновление отказывает.

Тестовая БД и ключ предназначены **только для QA**. Они не подходят для настоящих данных. Нельзя подменять сохранённый production-секрет на тестовый.

## Откат

После изменения схемы v12 JUDGE 0.10.0 **не должен запускаться** на той же базе: старый код откажет из-за более новой схемы. Откат означает восстановление предыдущей **резервной копии схемы v7** с соответствующим неизменённым HMAC-ключом. Данные, созданные в 0.15.0 после обновления, автоматически назад не перенесутся.

## Ограничения

Миграция проверена на тестовой базе из настоящего кода, но **не выполнялась на вашей производственной базе** и не доказывает отсутствие особых случаев в неизвестных рабочих данных. До изменения удалённого сервера нужна копия production, dry-run и независимое восстановление.
