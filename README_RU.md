# ADVERSE JUDGE 0.15.0 — DEVELOPMENT WAVES 6–10

**Рабочий локальный пилот, расширенный пятью новыми волнами разработки поверх версии 0.10.0. НЕ production, НЕ опубликован на рекламных платформах A–G.**

JUDGE помогает превратить неопределённое рекламное обещание в структурированный бриф. Пользователь проходит ограниченные редакторские действия, сохраняет вердикт, запрашивает возражение свидетеля и проверяет понятность двух формулировок на приглашённых читателях. Состояние хранится сервером в SQLite, а не придумывается ИИ. Все новые функции действительно подключены к HTTP API и браузерному интерфейсу.

## Волны 6–10: от кампании до файла рекламного выпуска

| WAVE | Проверенная функция | Реализация |
| --- | --- | --- |
| **6 — CAMPAIGN PLANNER** | Создать кампанию, выбрать рабочую команду, зафиксировать цель/аудиторию/формат, явно прикрепить вердикт из опубликованного команде дела. Каждая правка увеличивает редакцию и сбрасывает старое одобрение. | `server/production.mjs`, `/api/production/campaigns`, `public/production.mjs` |
| **7 — EVIDENCE REGISTRY** | Зарегистрировать конкретное основание и расположение источника, передать его на изучение другому участнику, сохранить дату и проверяющего. Автор источника не может сам отметить его изученным. | `campaign_evidence`, `reviewEvidence`, `preflight` |
| **8 — APPROVAL WORKFLOW** | Отправить кампанию на согласование, получить решение *другого* редактора, запросить изменения, отклонять устаревшие версии, отозванные источники и одобрение сотрудника, утратившего полномочия. | `campaign_reviews`, `requestReview`, `decide`, `preflight` |
| **9 — CREATIVE STUDIO** | Создать и сохранить тексты для `search`, `social`, `email` на RU/EN/中文 с предельными размерами полей; получить осторожную шаблонную подсказку из реального брифа. Без фантазий о CTR и без скрытой генерации. | `campaign_creatives`, `checkCreative`, `suggest` |
| **10 — RELEASE CENTER** | После независимого согласования сформировать защищённый от случайного изменения JSON-снимок редакции с SHA-256, проверить его офлайн; повторное создание того же снимка не дублирует выпуск. | `campaign_releases`, `scripts/verify-release.mjs` |

**Запуск нового пути:** войдите в локальную учётную запись → создайте команду в «Команды» → опубликуйте ей завершённое дело JUDGE → откройте «Кампании» → создайте кампанию → прикрепите бриф → добавьте основание → второй участник отметит изучение → создайте рекламные варианты → направьте на независимое согласование → скачайте пакет выпуска в JSON. Один и тот же участник не может подменить работу двух разных пользователей.

**Важно:** «изучено» означает личное заявление другого человека, а не независимую проверку подлинности; «согласовано» — редакторское решение, а не юридическое заключение; выпуск файла **не означает отправку рекламы** в A–G. Никаких настоящих API A–G в проекте по-прежнему нет.

Конкретные контрактные сценарии, схема БД v12, угрозы и тесты: `docs/WAVES-06-10-IMPLEMENTATION.md`, `reports/WAVES-06-10-TEST-REPORT.md`, `docs/UPGRADE-V010-TO-V015-RU.md`.

## Запуск на Windows/Linux/macOS

Требуется **Node.js 22.13+** (проверено на 22.16.0). Пакеты из npm ставить не нужно.

```bash
npm start
```

Открыть **http://localhost:3000**. На Windows можно дважды нажать `START_WINDOWS.cmd`. Сервер по умолчанию слушает только loopback и создаёт `data/judge.sqlite` при первом запуске.

**Первая полноценная сессия:** «Открыть первое дело» → «Уточнить обещание» → «Собрать формулировки» → «Зафиксировать бриф» → «Создать слепой тест» → «Пригласить читателя». Для **WAVE 1** нажать «Аккаунт», зарегистрировать тестовую учётную запись, открыть «Команды», создать пространство, пригласить другую учётную запись и опубликовать туда своё дело. Для **WAVE 2** из дела с открытым слепым тестом создать исследование, записав гипотезу до получения ответов. Для **WAVE 3** изменить язык RU/EN/中文 в верхней панели.

**Без установки** можно открыть `dist/JUDGE-ADVERSE-preview.html`: это статический локальный разбор, **не** серверный режим. Он не выполняет реальные регистрации, приглашения, совместную работу, исследования, голосования и внешние передачи.

Для проверки базы, включив HMAC-режим, задайте `JUDGE_LEDGER_SECRET` **до первого запуска**, не теряйте ключ и никогда не публикуйте его. Смена ключа для существующей базы без штатной миграции **не поддерживается**: приложение откажет в запуске, вместо того чтобы тихо отказаться от проверки. Режим без ключа (SHA256) выявляет обычное повреждение данных, **но не защищает от злоумышленника, имеющего право менять базу**. Подробнее `docs/DEVOPS-SECURITY-RU.md`.

## Миграция с версии 0.10.0

1. Остановить старый JUDGE и сделать проверенную резервную копию папки `data/` целиком.
2. Не переписывать исходную папку поверх работающей версии. Распаковать новый релиз отдельно.
3. Скопировать прежнюю `data/judge.sqlite` в новую `data/` или указать старое расположение через `JUDGE_DB`. Если используются файлы WAL/SHM, сначала **полностью остановить сервер**, затем переносить корректный snapshot/backup.
4. Сохраните **точно прежнее** значение `JUDGE_LEDGER_SECRET`. Нельзя включать HMAC на существующей базе, ранее работавшей без ключа, или менять секрет без отдельной проверенной процедуры миграции: код намеренно отклоняет смену режима.
5. Запустить и выполнить `npm run verify`; проверить свои старые дела, сеансы и результаты слепого тестирования.
6. Откат на 0.10.0 возможен **только вместе со старой резервной копией SQLite**: старый код не знает новую схему v12.

Детальный регламент: `docs/UPGRADE-V010-TO-V015-RU.md`. Автоматизированная репетиция миграции базы, созданной кодом 0.10.0, находится в `tests/migration-v010-to-v015.test.mjs` и `tests/fixtures/v010.sqlite`.

## Что не сделано — важные ограничения

- **0 из 7 реальных рекламных сайтов A–G подключены.** Нет URL и подтверждённых контрактов. Успешные тесты Wave 4 проводились только с **синтетическим локальным принимающим сервером**. Копирование брифа не доказывает создание объявления.
- **Учётные записи остаются локальными**: нет подтверждения email, общего SSO семи сайтов, MFA, восстановления пароля, коммерческого биллинга. Командные приглашения являются bearer-links и не ограничены конкретным подтверждённым адресом email.
- **SQLite — один узел**, нет удалённого Postgres, автоматического зашифрованного резервирования вне сервера, внешнего мониторинга и проверенного production-развёртывания.
- **Английский и китайский интерфейсы частичные.** Основные разделы и кнопки переведены, но часть длинных сценарных реплик и второстепенных пояснений остаётся на русском. Перед глобальным релизом нужен полный перевод/линтинг.
- **Evidence Room не защищён от Sybil/бот-голосов**: одна ссылка — один ответ, но злонамеренный пользователь может приглашать несколько контролируемых аккаунтов или сессий. Голоса показывают предпочтения добровольно приглашённых читателей, не CTR, не продажи и не репрезентативную выборку.
- Услуги OpenAI/LLM опциональны; без ключа и явного разрешения действует сценарный режим. Не заявляем, что ИИ прошёл живые платные испытания в этом релизе.

## JUDGE 0.30.0 · ПЯТЬ НОВЫХ ВОЛН (WAVE 21–25)

**Новая основная версия локального пилота: 0.30.0**. Старые функции JUDGE 0.25.0 сохраняются, а к кампании добавлена страница «WAVE 21–25» с пятью операционными сценариями:

1. **Подтверждение email и восстановление пароля** — только через внешний защищённый почтовый webhook, если оператор его настроил. Без провайдера код не появится и не выводится в ответах API.
2. **История редакций** — сравнение последнего утверждённого пакета с текущими рекламными текстами и безопасное восстановление в новый неутверждённый черновик.
3. **Массовый импорт CSV** — проверка, просмотр итогов и подтверждение импорта без повторных строк. Цифры помечены как ручные, не как подтверждённые показатели внешней платформы.
4. **Очередь доставки** — отдельная очередь подписанных серверных пакетов, retry с идемпотентностью, пример настоящего HTTP-получателя в интеграционных тестах. **Без проверки реальных URL платформ A–G отправка не выполняется**.
5. **Операционная диагностика** — реальные блокеры публичного запуска, проверка backup и локальная запись диагностического отчёта; пользователь видит только состояние своей команды.

База SQLite мигрирует **22 → 27**. Миграция обратно без восстановленной резервной копии не поддерживается.

Полное описание: `docs/WAVES-21-25-IMPLEMENTATION.md`. Безопасное обновление: `docs/UPGRADE-V025-TO-V030-RU.md`.
